# SMC 引擎方法論規格

本文件說明 `src/smc/*` 每個模組的精確判定規則，讓任何人都能驗證（或質疑）程式的結論。
所有函式皆為純函式：相同輸入必得相同輸出，且**只讀取索引 ≤ 當前 K 棒的資料**。

---

## 1. 擺動點 Swings (`swings.js`)

### 1.1 分形偵測
索引 `i` 是擺動高點，若對所有 `j ∈ [1, n]`：

```
high[i-j] <  high[i]   （左側嚴格大於）
high[i+j] <= high[i]   （右側容許等值 → 雙頂仍可辨識）
```

擺動低點取對稱條件。`n` 即「靈敏度 strength」：
- 內部結構（Internal）預設 `n = 2` → 抓細微轉折，用於進場
- 擺動結構（Swing）預設 `n = 7` → 抓主要轉折，用於定方向

每個擺動點記錄 `confirmedAt = time[i + n]`：**它在 n 根之後才成立**，這是避免未來函數的關鍵。

### 1.2 高低交替化
相鄰兩個同型別擺動點只保留更極端者（兩個高點保留較高者）。
這一步讓結構序列必定是 H → L → H → L …，BOS/CHoCH 的判定才不會被雜訊干擾。

### 1.3 標籤
比較前一個同型別擺動點：更高的高點 = HH、更低的高點 = LH、更高的低點 = HL、更低的低點 = LL。

### 1.4 交易區間 Dealing Range
取最後一個擺動高與最後一個擺動低。
若價格已突破此區間（新高或新低），區間會**自動延伸到新的極值**，
否則折溢價百分比會出現 >100% 或 <0% 的無意義數字。

## 2. 市場結構 (`structure.js`)

以 K 棒逐根前進的方式模擬實時判定：

```
for each candle i:
    將 confirmedAt == i 的擺動點納入待突破清單
    若 breakLevel(i) > pendingHigh.price:
        type = (trend == bearish) ? CHoCH : BOS
        trend = bullish
        strongLow = 區間 [pendingHigh.index, i] 的最低點   ← 新的受保護低點
        pendingHigh = null（等待新的擺動高確認）
    對稱處理向下突破
```

- `breakLevel` 預設為收盤價（嚴謹），可切換為影線（敏感）
- **BOS** = 順著當前趨勢方向突破 → 延續
- **CHoCH** = 逆著當前趨勢方向突破 → 性質轉變（反轉的第一個訊號）
- **強高低點**：造成突破的那個極值，機構的防守位置
- **弱高低點**：尚未取得流動性、後續容易被掃的位置

雙尺度：`dualStructure()` 以兩組 strength 各跑一次，輸出 internal 與 swing 兩套結果。

## 3. 流動性 (`liquidity.js`)

### 3.1 流動性池
逐一掃過擺動點，若與既有池的價差 ≤ `ATR × tolAtr`（預設 0.18）且同側，則併入該池：
- `touches` +1，`equal = true`（即 EQH / EQL）
- 價格取更極端者

池的強度：`30 + touches×18 + (equal ? 15 : 0) + (swept ? −25 : +10)`，上限 100。

### 3.2 掃除 Sweep
對每個擺動點向後搜尋（上限 60 根），第一次穿越時判定：

```
擺動高：high[i] > level 且 close[i] < level  → 掃買方流動性（看空訊號）
擺動低：low[i]  < level 且 close[i] > level  → 掃賣方流動性（看多訊號）
```

深度以 `|穿越幅度| / ATR` 計，作為強度依據。

### 3.3 誘導 IDM
取最近一次結構事件推動腿中「最後一個反向的次級擺動點」，並向後追蹤是否被取走。
IDM 尚未被取走時，在 POI 進場的勝率通常較低。

### 3.4 流動性吸引
以 `Σ strength / 相對距離` 分別加總上方與下方未掃除的池，
兩者相差 20% 以上即判定為 buyside / sellside 吸引。

## 4. 公允價值缺口 (`fvg.js`)

```
多方 FVG：low[i]  > high[i-2]     區間 = [high[i-2], low[i]]
空方 FVG：high[i] < low[i-2]      區間 = [high[i], low[i-2]]
```

- 以 `size / ATR ≥ fvgMinAtr`（預設 0.25）過濾雜訊
- **量能不平衡 VI**：實體之間有缺口但影線重疊，門檻為 FVG 的 1.5 倍
- **CE（Consequent Encroachment）** = 缺口 50% 中線，常用精準進場價
- 狀態機：`fresh → partial → filled`；若收盤穿越到另一側 → `inverted`（IFVG，方向反轉）
- 品質分數：大小、位移強度、狀態、年齡

## 5. 訂單塊與破壞塊 (`orderblocks.js`)

對每個結構事件（BOS / CHoCH）：

1. 找出推動腿起點：事件區間內的最低點（看多）或最高點（看空）
2. 從突破棒往回找**第一根反向 K 棒** → 即 OB
3. 驗證位移：`推動腿幅度 / ATR ≥ minDisplacementAtr`（預設 1.0），未達標則捨棄
4. 區間取高低點（預設）或實體（可切換）
5. 生命週期：
   - 價格觸及 → `tapped`，並記錄消耗百分比
   - 消耗 ≥ 98% → `mitigated`
   - 收盤穿越另一側 → `breaker`（方向反轉）
6. 品質分數（0–100）：

```
40
+ min(25, 位移ATR × 8)
+ min(12, (相對量能 − 1) × 12)
+ 12  若內含 FVG
+ 10  若形成前掃過流動性
+ 6   若由 CHoCH 造成
+ 6   若屬 swing 級別
+ 8 / +2 / −15 / −8   依 fresh / tapped / mitigated / breaker
− min(12, 年齡 / 60)
```

同向且重疊率 > 60% 的區塊只保留分數較高者，避免圖面雜訊。

## 6. 折溢價與 OTE (`zones.js`)

```
ratio = (price − rangeLow) / (rangeHigh − rangeLow)   （夾在 0–1）
ratio > 0.55 → 溢價 Premium（利於做空）
ratio < 0.45 → 折價 Discount（利於做多）
其餘         → 均衡 Equilibrium
OTE = 回撤 0.618 – 0.79，甜蜜點 0.705
```

POI 綜合排序分數：

```
rank = 品質分數
     + 12  若與偏向同向（否則 −8）
     − min(25, |距離現價%| × 9)
```

`stackConfluence()` 會把價格重疊（預設 0.12% 內）的同向 POI 合併為「匯流堆疊」，分數加成。

## 8. 偏向評分 (`engine.js`)

| 因子 | 最大貢獻 |
|---|---|
| 擺動結構趨勢 | ±34 |
| 內部結構趨勢 | ±16 |
| 折溢價位置 `(0.5 − ratio) × 24` | ±12 |
| 流動性吸引差 | ±12 |
| 價格 vs EMA200 | ±10 |
| 價格 vs EMA50 | ±8 |
| RSI 偏離 50 | ±8 |

總分夾在 -100 ~ +100；≥ +25 看多、≤ −25 看空、其餘中性。
**每個因子的實際得分都會顯示在介面上**，而不是只給結論。

## 9. 交易計畫 (`setups.js`)

1. **方向**：`0.6 × 高週期偏向 + 0.4 × 進場週期偏向`；兩者強烈分歧時標註警告
2. **POI**：同向、未消耗、且距離現價在 `max(5 ATR, 3.5%)` 內的最高排序者
3. **進場**：若現價已在區間內 → 市價；否則掛在區間邊緣等回測
4. **停損**：POI 另一側與內部結構受保護高低點取較外者，加 `0.35 ATR` 緩衝，最小風險 `0.3 ATR`
5. **目標**：最近未觸及流動性 → 關鍵時間價位 → 區間極值 → 1:3 延伸；過濾 `<0.8R` 與 `>12R`
6. **匯流檢查表**（權重合計 112 → 正規化為 100 分）：

| 條件 | 權重 |
|---|---|
| 高週期偏向一致 | 18 |
| 進場週期已出現 CHoCH / BOS | 15 |
| 價格位於正確的折價／溢價側 | 12 |
| 進場 POI 未被消耗 | 12 |
| 進場前已掃除反向流動性 | 12 |
| POI 具多重匯流 | 10 |
| 風報比達標 | 10 |
| 目標方向存在未觸及流動性 | 10 |
| 均線／動能支持 | 8 |
| 位於 Killzone | 5 |

評級：A+ ≥ 80、A ≥ 68、B ≥ 55、C ≥ 42、D < 42。
`valid = 分數 ≥ 42 且最終風報比 ≥ min(1.5, 設定值)`；未達標者在介面上明確標示。

## 10. 訊號回測 (`backtest.js`)

```
每隔 step 根 K 棒：
    用 candles[0 .. i] 重新分析（絕不看未來）
    若計畫有效且分數 ≥ minScore：
        市價訊號 → 立即以 entry 成交
        限價訊號 → 等待最多 entryWindow 根，價格觸及 entry 才成交；
                   期間若收盤穿越停損則放棄
        成交後往後最多 horizon 根，判斷先觸 TP1 或 SL
        同一根同時觸及 → 保守假設為停損
    同一時間只持有一筆
```

輸出：勝率、期望值（平均 R）、總 R、獲利因子、最大回撤（R）、最長連敗、分級表現、權益曲線。
**不含手續費與滑價**，因此應視為「訊號品質檢驗」而非完整策略績效。

## 已知限制

- SMC 本質上是主觀框架；本程式是其中一種量化詮釋，不同流派的定義可能不同。
- 擺動點需要 `n` 根之後才確認，因此結構事件天然有落後性（這是正確的，不是缺陷）。
- 回測不含手續費、資金費率、滑價與部分出場策略。
- Demo 模式為隨機漫步合成資料，期望值理論上趨近於零 —— 它用來驗證程式，不是用來證明策略有效。
