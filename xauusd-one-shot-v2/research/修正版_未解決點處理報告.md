## 先更正一個重要結論

舊版 `BE1.5 / TP5` 出場程式把「48小時」實作成 `576 根 M5 K棒`。市場週末沒有K棒，因此 **576根M5不等於48個曆時小時**。這會讓部分持倉跨週末後實際存活超過48小時。

我已把它改成：`entry_timestamp + 48 calendar hours`，到期限後在第一個可取得的市場報價退出。重新回測後，策略仍保持正期望，但原先「6% ratchet 的單一路徑曾由60U達到10000U」**不再成立，必須撤回**。

## 最低手數問題：已量化

V2 的 321 筆原始 BE1.5/TP5 交易中，初始停損距離 `2 × M15 ATR`：

- 最小：約 3.68 美元/盎司
- 中位：約 11.50 美元/盎司
- 90分位：約 25.14 美元/盎司
- 最大：約 52.30 美元/盎司

若某 MT5 標準 XAUUSD 為 100oz/lot，最低 0.01 lot，則 0.01 lot = 1oz。60U 帳戶的 6% 風險預算只有 3.60U；光停損價格距離的最小樣本就約 3.68U，還沒加佣金/滑點，因此 **0.01 lot 的標準黃金在60U上無法精準執行6%風險**。

以100oz/lot近似計算，可符合60U×6%=3.60U停損預算的歷史訊號比例：

| 最低可下手數 | 可執行比例（未加額外成本） |
|---:|---:|
| 0.01 | 0.0% |
| 0.005 | 21.2% |
| 0.003 | 51.7% |
| 0.002 | 74.5% |
| 0.001 | 97.8% |
| 0.0005 | 100% |

所以真正的解法不是 EA 強制下 0.01，而是 **EA 必須讀取實際 Symbol Properties，若最小手數會超過風險預算就跳過交易**。本包新增 `MT5_SymbolProbe.mq5` 與 `RiskSizing.mqh`，使用 `OrderCalcProfit` / `OrderCalcMargin` 依券商商品規格計算，不硬寫合約大小。

若要讓60U幾乎完整執行這套策略，實務上需要更細的黃金商品粒度（例如可做到約0.001 lot等級，或更小合約規格）；具體能否交易以實際券商 Symbol Properties 為準。

3. 對 M1 同時觸及 SL/TP 的少數模糊交易，再下載 tick 資料重播。

本包新增 `external_validation_runner.py`，策略參數完全鎖死，不做搜尋。當執行環境有外網時，可使用 `dukascopy-go` 下載 bid/ask M1 後直接驗證。此對話執行環境無法對外下載大檔，因此**外部 holdout 尚未實際跑完**，不能把它標成通過。

## 跳空／底線

「里程碑底線」不是保證止損。市場跳空時，成交可以穿過 SL。測試過週五強制平倉，2026H1 會掉成負期望，因此不能只為降低跳空就偷偷加入正式策略。這項風險能做的是：

- EA 用實際風險預算 + 額外 gap buffer 計算倉位。
- 不允許最小手數超出風險上限。
- 可另做「週末不持倉」版本，但必須重新通過 external holdout 才能採用。

除非使用提供 guaranteed stop 的商品/券商機制，否則任何一般 MT5 市價/停損系統都無法保證底線絕不被跳空穿越。

## 真正仍無法在今天解掉的兩件事

1. **未來 forward 資料**：未來行情尚未發生，不能用更多歷史回測替代。
2. **你的實際 MT5 券商商品規格**：程式已能自動檢查，但必須在你的 MT5 帳戶上執行 `MT5_SymbolProbe.mq5` 才能取得真實 volume min/step、contract size、tick value、margin 等值。

其餘程式口徑、最低手數風險與48小時錯誤已處理。

## 給 Work 模式的硬性要求

Work 不得沿用舊版「60U→10000U 已歷史命中」結論。必須以本修正版為最高優先級：

- Entry 參數鎖死。
- Exit 使用真正 48 個曆時小時，不是 576 根K棒。
- BE：收盤確認 +1.5R 後，下一根才移到進場價。
- TP：5R。
- 倉位必須以 `OrderCalcProfit` 計算，不能假設 0.01 lot 一定可用。
- 最小手數超過風險預算：跳過，不得強制下單。
- 未通過 external true Bid/Ask holdout 前，不得宣稱策略完成驗證。
